# Security Policy

We take the security of this project seriously. Thank you for helping keep it and its users safe.

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please report it through responsible disclosure rather than opening a public GitHub issue.

To report a vulnerability, email **security@example.com** with the following details:

- A description of the issue and its potential impact
- Steps to reproduce, or a proof-of-concept
- The affected version(s) and any relevant configuration
- Your name and contact information (optional, for credit)

You should receive an initial response within **48 hours** acknowledging receipt of your report. We will work with you to understand and validate the issue, and we will keep you informed about progress toward a fix.

Please do **not** disclose the vulnerability publicly until we have had a reasonable opportunity to investigate and release a fix.

## Supported Versions

Only the latest major version of this project receives security updates.

| Version        | Supported          |
| -------------- | ------------------ |
| Latest major   | :white_check_mark: |
| Older versions | :x:                |

If you are running an older major version, please upgrade to the latest release to ensure you receive security fixes.

## Disclosure Policy

We follow a coordinated disclosure model:

1. Reporter submits the vulnerability to security@example.com.
2. We acknowledge receipt within 48 hours and begin investigation.
3. We work on a fix and coordinate a release timeline with the reporter.
4. Public disclosure should wait at least **90 days** after the initial report, or until a fix has been released — whichever comes first — unless an alternate timeline is mutually agreed upon.

This window gives maintainers and downstream users time to apply the fix before details become public.

## Scope

This policy applies to the code and resources contained in this repository. Vulnerabilities in third-party dependencies should be reported directly to the maintainers of those projects.

## Thanks

We appreciate the security research community's efforts in responsibly disclosing issues and helping us protect our users.
