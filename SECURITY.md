# Security Policy

We take the security of this project seriously. This document describes how to
report vulnerabilities and what to expect after you do.

## Supported Versions

Security fixes are issued for the latest major version only. Older majors do
not receive backported patches.

| Version       | Supported          |
| ------------- | ------------------ |
| Latest major  | :white_check_mark: |
| Older majors  | :x:                |

## Reporting a Vulnerability

Please **do not** open a public GitHub issue for security reports. Instead,
email the details to **security@example.com**.

When reporting, include as much of the following as you can:

1. A description of the vulnerability and its potential impact.
2. Steps to reproduce, including any proof-of-concept code or configuration.
3. The affected version(s) or commit SHA.
4. Any suggested mitigation, if known.

## Response Process

- We will acknowledge your report within **48 hours** of receipt.
- We will investigate, keep you informed of progress, and coordinate a fix and
  release timeline with you.
- Once a fix is available, we will credit the reporter (unless anonymity is
  requested) in the release notes.

## Responsible Disclosure

We follow a coordinated disclosure model. Please give us a reasonable window to
investigate and ship a fix before publishing details. We ask that public
disclosure wait **90 days after the initial report**, or until a fix has
shipped — whichever comes first. If we need additional time, we will discuss
an extension with you.

Thank you for helping keep this project and its users safe.
